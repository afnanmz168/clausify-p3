\section*{Seeds and splits}
\begin{itemize}[itemsep=2pt]
  \item Seed 42 for the split, all three trainings and every bootstrap.
  \item The split is \emph{made once} with \texttt{numpy.random.default\_rng(42).permutation}, saved to \texttt{artifacts/split.json}, and read from disk by every later script, so no script makes its own split.
  \item Extra presence-model seeds 43 and 44 (Section~\ref{sec:seeds}); split seeds 0--19 for Section~\ref{sec:splitvar}.
  \item Bootstrap: 10{,}000 resamples, \texttt{default\_rng(42)}, resampling whole contracts.
  \item Re-run validation split (Section~\ref{sec:v2}): 81 of the 408 training contracts, drawn with \texttt{default\_rng(42).permutation} over the training titles and saved as \texttt{retrain/v2\_fullwindow/runs/<tag>/val\_split.json}.
\end{itemize}

\section*{Known limits on exact repeatability}
\begin{itemize}[itemsep=2pt]
  \item Training on MPS does not give exactly the same weights every time, even on the same machine with the same library versions. Re-training every model in October 2026 with the same code and seed gave the August scores to within about 0.003 (transformer micro-F1 0.6943 $\rightarrow$ 0.6924; span token-F1 0.763 $\rightarrow$ 0.764), but not exactly.
  \item ROUGE-L in \texttt{summ\_pilot.py} is computed by our own longest-common-subsequence code (the same as in \texttt{test.ipynb}), not by the \texttt{rouge\_score} package, so scores from the two should not be mixed.
  \item The retrieval limit in Section~\ref{sec:ceiling} was measured over all 510 contracts, test contracts included (Section~\ref{sec:threats}).
\end{itemize}
